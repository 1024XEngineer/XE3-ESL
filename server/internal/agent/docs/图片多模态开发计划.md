# Agent 图片多模态开发计划

## 目标

在不破坏现有文字、语音、Tool Calling 和消息历史能力的前提下，让用户可以在 Agent 对话中上传图片，并由当前配置的千问模型理解图片后返回文字结果。

本计划采用分阶段交付方式。每完成并验收一个阶段，将对应条目前的 `[ ]` 改为 `[x]`，不要求一次性完成全部能力。

## 当前结论

- 当前文本模型为 `qwen3.7-plus-2026-05-26`。
- 该模型支持 Text、Image、Video 输入和 Text 输出，也支持 Function Calling。
- 当前项目不能使用模型的图片能力，主要原因是内部 AI 契约和千问适配器只支持字符串 `content`。
- Agent 消息协议当前只支持 `text` 和 `voice`，没有图片附件。
- Flutter 当前没有图片选择、预览和上传入口。
- OSS 已配置并用于语音文件，现有私有 Bucket、对象写入、删除和短期 Signed URL 能力可以复用。
- 当前 OSS 配置及对象存储客户端以 `audio/v1` 为固定前缀，需要在不影响语音链路的情况下增加独立的图片对象前缀。
- 图片资产仓储使用独立的 GORM Repository；现有 Agent pgx 仓储保持不变，两者复用同一个 pgx 连接池。

## 一期产品范围

一期支持：

- 用户从相册选择图片或拍照。
- 每条消息最多携带 4 张图片。
- 支持 JPEG、PNG、WebP。
- 单张原始图片最大 10 MiB。
- 服务端验证真实图片格式、尺寸和所有权。
- 服务端清除不需要的图片元数据，并限制最长边和总像素。
- 用户使用“文字问题 + 图片”提交消息。
- 千问返回文字结果。
- 图片消息可以进入历史记录并支持继续追问。
- 图片输入可以与现有 Function Calling 同时工作。

一期暂不支持：

- PDF、DOC、DOCX 等文档上传。
- GIF 动图、SVG、HEIC。
- 视频输入。
- 图片生成或图片编辑。
- 用户直接提交任意公网图片 URL。
- 助手 Markdown 中的远程图片加载。

### 建议模型

```go

const (
	ContentPartText     ContentPartKind = "text"
	ContentPartImageURL ContentPartKind = "image_url"
)

type ContentPart struct {
	Kind     ContentPartKind
	Text     string
	ImageURL string
}
```

最终命名以现有 `server/internal/ai` 的边界和评审结果为准。

### 建议数据关系

```text
agent_image_assets
  ├── owner_user_id
  ├── thread_id
  ├── object_key
  ├── content_type
  ├── size_bytes
  ├── width / height
  ├── checksum_sha256
  ├── status
  └── lifecycle timestamps

agent_message_images
  ├── message_id
  ├── image_asset_id
  └── position
```

图片资产与消息使用一对多关系，一条消息最多绑定 4 张图片。

## 阶段四：上下文、运行循环和历史恢复

### 任务

- [x] 在创建 Run 前解析并锁定当前消息的图片资产。
- [x] 调用模型前重新检查图片所有权、Thread 归属和可读状态。
- [x] 为每次模型调用生成新的短期 Signed URL。
- [x] 将用户文字与图片按稳定顺序加入模型请求。
- [x] 保证工具循环后续迭代仍保留本次图片上下文。
- [x] 为历史消息上下文选择增加独立的图片数量预算，优先保留最新图片。
- [x] 在近期上下文窗口内按需重新附带原图。
- [x] Thread Summary 记录模型已经确认的图片事实，避免长期重复发送原图。
- [x] 图片被删除后保留消息文字，但不再尝试向模型或客户端读取原图。
- [x] Retry 使用原 Run 已锁定的图片集合，不允许客户端在 Retry 时替换图片。

### 上下文策略

千问调用是无状态的。为了支持“再看看图中第二段”之类的追问：

1. 图片消息仍处于近期消息窗口时，后续调用重新附带相关原图。
2. 每次调用重新生成 Signed URL，不能复用过期 URL。
3. 图片超出上下文窗口后，优先使用已经生成的 Thread Summary。
4. 如果产品后续支持“重新查看早期图片”，应通过稳定图片资产 ID 显式重新选入上下文。

### 验收

- [x] 首轮图片问答的确定性请求链路正确。
- [x] 后续文字追问仍会引用近期图片内容。
- [x] Tool Call 前后图片上下文不丢失。
- [x] Retry 结果使用原始图片集合。
- [x] 每次模型调用重新签名，过期 Signed URL 不影响新调用。
- [x] 图片输入计入独立预算，不只依赖字符数量预算。

- [x] Signed URL、对象 Key 和图片原始内容不得进入日志。

### 限额建议

```text
AGENT_MAX_IMAGES_PER_MESSAGE=4
AGENT_MAX_IMAGE_BYTES=10485760
AGENT_MAX_IMAGE_PIXELS=16000000
AGENT_IMAGE_LONG_EDGE=2048
AGENT_CONTEXT_MAX_IMAGE_TOKENS=16000
OSS_IMAGE_PREFIX=image/v1
```

这些数值是产品侧一期上限，不必直接采用供应商允许的最大值。
