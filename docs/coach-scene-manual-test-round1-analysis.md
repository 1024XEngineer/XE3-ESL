## 1. 结论摘要

第一轮证明了明确具体场景和普通咨询链路基本可用，但也暴露出一个更基础的产品边界问题：**四个大类不是四个具体场景，不能因为用户只说了大类就自动选一个内部默认场景。**

1. 原始标签统计为 24 次通过、12 次不通过，通过率 66.7%。
2. `TRIAL-001` 的具体场景创建为 11/12 通过；唯一失败缺少足够差异证据，需要按统一标准复核。
3. `TRIAL-003` 的普通咨询或未来意向为 12/12 通过，没有观察到误创建。
4. `TRIAL-002` 的原始预期是“先收集关键信息或列有限选项”。12 次实际行为全部提前锚定了某个默认场景：7 次直接展示默认预览，5 次先询问是否创建已经擅自选定的默认场景；没有一次完成了正确的场景澄清。
5. `TRIAL-002` 的人工标签有 1 次被记为通过，但按该 Case 自身的预期应为不通过。因此原始数据应保留，复核结论应记为 12/12 未满足原预期。

## 3. 领域模型复核：大类、目录场景和定制场景

### 3.1 四个大类不是四个小场景

当前代码中的四个 `PracticeExperience` 是分类层：

| 大类 | 具体目录场景示例 |
|---|---|
| `INTERVIEW` | 英文自我介绍、招聘初筛、行为面试、项目经历深挖、系统设计口述 |
| `IELTS_SPEAKING` | 一个 IELTS 口语目录场景，下有 Part 1、Part 2、Part 3、完整模考等练习选项 |
| `WORKPLACE` | 进度与风险汇报、会议表达异议、跨团队对齐、谈判、客户需求澄清等 |
| `LIFE_AND_TRAVEL` | 自我介绍与寒暄、酒店入住、机场值机、餐厅点餐、购物、租房等 |

目录中确实存在 `default_scene_id`，但它是系统内部的推荐数据，不代表用户只说大类时已经选择了该场景。用户不应被要求说“使用默认”；助手也不应把默认值直接暴露成对话话术。

### 3.2 `TRIAL-002` 的实际行为

| Case | 用户只提供的信息 | 实际行为 | 原预期 |
|---|---|---|---|
| IELTS | 雅思口语，但没想好 Part | 完整模考预览，或询问是否创建 IELTS 口语 | 询问 Part 1、2、3 或完整模考 |
| 面试 | 面试练习 | 直接使用英文自我介绍 | 询问面试类型或目标 |
| 职场英语 | 职场英语，但不知道练什么 | 选择进度与风险汇报，再询问是否创建 | 列出有限职场场景选项 |
| 生活与旅行 | 旅行英语 | 直接使用自我介绍与寒暄 | 询问酒店、机场、餐厅等场景 |

这说明问题不是单纯的 `REQUEST_CREATE` / `PROPOSE_CREATE` 分类不稳定，而是把两个问题混在了一起：

```text
用户是否授权现在准备练习？
用户是否已经提供足够信息选定具体场景？
```

前者可以是“是”，后者仍然可以是“否”。

## 4. 修订后的产品契约

```text
明确创建 + 已匹配一个具体目录场景
→ 生成预览
→ 用户确认后创建 Session
```

```text
明确创建 + 只指定大类 / 明确说没想好
→ 自然追问或列出有限选项
→ 不生成预览，不创建 Session
```

```text
具体请求无法由目录承载
→ 在支持通用定制的领域创建 CUSTOM 场景
→ 保留用户提供的情境、角色和目标，不臆造关键事实
```

```text
用户说“你帮我选”
→ 助手可以结合上下文给出有理由的推荐
→ 不使用“默认场景”等系统术语，并在真正生成预览前保持可修改、可取消
```

当前代码已有 `CUSTOM` 执行边界，但只支持 `WORKPLACE` 和 `LIFE_AND_TRAVEL`。IELTS 和面试仍应使用专用目录/准备流程，不能静默伪造成通用定制场景。

## 5. 仍然成立的问题

### BUG-ROUND1-001：大类请求被过早解析为默认小场景

- 等级：P1
- Issue：#783
- 影响层：Preview 场景解析与人工测试契约

典型输入：

```text
帮我创建一个雅思口语练习，但我还没想好练哪一部分。
我想创建一个职场英语练习，但不知道练什么。
```

正确行为应为：

```text
REQUEST_CREATE
→ NEEDS_CLARIFICATION
→ 自然询问或展示有限候选
→ 不创建 Plan / PendingAction / Session
```

如果目录中没有合适的具体交互模式，则应在支持通用定制的领域进入：

```text
REQUEST_CREATE
→ CUSTOM
→ 生成定制预览
→ 等用户确认
```

### DATA-ROUND1-002：人工判定标准不一致

- 等级：P2（测试质量问题）

相同或近似行为在不同人员记录中被标记为不同结果。后续测试必须把以下字段分开记录：

- 是否调用 Preview Tool；
- 场景解析结果：Catalog / Needs Clarification / Custom；
- 是否产生预览 Plan；
- 是否创建 PendingAction；
- 用户确认前是否创建 Session；
- 最终使用的具体 Scene 和 Practice Mode。
